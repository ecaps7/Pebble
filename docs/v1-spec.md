# 项目约定

## 项目目标

构建一个持续运行、可成长、具备跨工具执行能力的个人 Agent。它能够在个人资料、邮件、日历和持久规则之间共享上下文，并通过用户确认安全完成真实事务。

## 约定

| 项目项   | 约定                                                         |
| -------- | ------------------------------------------------------------ |
| 部署方式 | 单用户单实例部署；凭证、规则与任务状态在该实例内持久化。 |
| 主要交互 | 对话式交互，支持手机 Web 发起任务、查看进度、编辑草稿和确认操作；任务不依赖始终开启的桌面对话窗口。 |
| 个人资料 | 持久化保存、索引和检索资料；支持资料更新；回答与执行决策可定位到来源。 |
| 邮件     | 接入 Gmail；支持持续检查并获取新邮件、查询历史邮件与关联线程、生成/编辑草稿、用户确认后发送；重复检查不得重复处理或发送同一封邮件。 |
| 外部服务 | 首版接入 iCloud Calendar；支持日程查询、冲突检查和事件创建。外部写操作统一采用 Preview → Confirm → Execute。 |
| 能力组合 | Gmail、个人资料、iCloud Calendar 与 Memory/Skills 共享任务上下文，可完成跨工具完整任务。 |
| 能力成长 | 用户纠正持久化为可读、可改的 Rule/Memory；反复成功的流程可沉淀为 Skill/Workflow；自主沉淀的 Skill/Workflow 须经用户审核确认后才能投入生产，已生效内容在新会话中继续应用。 |
| 安全原则 | 具有副作用的外部写操作必须先展示关键内容及影响，并获得用户明确确认后执行。 |
| 可维护性 | 核心规则、Skills/Workflows 与关键配置保持可读、可修改，并通过 Git 管理版本。 |

## 核心能力

### 个人资料

- 支持用户资料的持久化保存、索引、检索和更新。

### External Services

#### Gmail

- 能够持续获取新邮件，而不是仅在用户主动查询时临时读取。
- 新邮件同步后自动启动 Agent 处理，由模型判断邮件内容并决定后续处理动作；涉及外部写操作时仍需用户明确确认。
- 处理当前邮件时，应能关联同一线程或相关历史往来。
- 回复采用“生成草稿 → 用户编辑/审阅 → 明确确认 → 发送”的流程。
- 保存邮件处理及发送记录，重复检查不得重复处理或发送同一封邮件；重复确认不得重复发送同一项已完成的回复。
- 发送结果不确定时，应先核实实际结果，不得直接再次发送。

#### iCloud Calendar

- 查询日程
- 检查时间冲突
- 生成日程预览
- 用户确认后创建事件

### Agent Runtime

Agent 根据用户意图组合个人上下文和不同工具完成任务，而不是让用户逐个调用功能。

在本规格约定的范围内，处理动作、工具组合、执行后的后续处理，以及规则和 Skill 的沉淀时机与内容，均由模型自主判断，不预设固定业务处理流程。模型决策仍须遵守外部写操作确认、信息不明确时追问和邮件去重等约束。

系统持续检查新邮件，任务执行不依赖始终开启的桌面对话窗口。用户可以从手机 Web 发起任务、查看进度、编辑草稿和确认操作。

写操作统一遵循：

```
Prepare → Preview → Confirm → Execute
```

保存日程预览、邮件草稿及其最终确认内容，用户关闭或刷新页面后仍可查看和编辑待确认内容。用户完成编辑后，对最终预览内容明确确认即可执行；日程创建与邮件发送分别确认，执行内容必须与对应确认内容一致。内容修改后，原有确认不再适用于修改后的版本。

根据实际工具结果准确反馈执行情况。例如日程已创建但邮件发送失败时，应分别说明，不能将整个任务报告为成功。

### 能力成长

- 用户纠正：沉淀为持久规则，例如字段解释、偏好、确认习惯等。
- 成功流程：对于重复出现且稳定成功的任务，将处理流程沉淀为可读、可改的 Skill/Workflow。
- 规则与 Skill 既可以由模型自主判断并沉淀，也可以由用户明确触发；沉淀后的内容仍须遵守本规格的执行约束。
- 自主沉淀的 Skill/Workflow 先保存为草稿，Agent 应在对话中提示用户查看。草稿须展示触发词、必要参数、执行流程及安全性信息，包括涉及的工具、外部副作用和确认要求。
- 用户可审阅、修改草稿；只有用户明确确认最终草稿中的触发词、必要参数及安全性等信息后，该 Skill/Workflow 才能投入生产。未经确认的草稿不得被 Agent 应用或执行，在新会话中同样不得生效。
- Skill/Workflow 投入生产的确认不替代执行时对具体外部写操作的确认。
- 已生效的规则和 Skill 在新会话中继续应用，并允许用户检查和修改。
- 规则与 Skill 通过 Git 管理，能够查看版本变化和回退。

## 端到端验证场景

> 用户说：“帮我处理这封活动邀请。”Agent 需要从邮件理解任务，并综合个人资料和日历状态，最终在用户确认后完成日程创建和邮件回复。

新活动邀请邮件同步后，也应自动启动 Agent 处理，按同样的约束完成以下场景。

1. 读取并解析指定 Gmail 邮件，识别活动名称、时间、地点、组织者、回复要求等信息。
2. 关联相关邮件线程和历史往来，补充当前邮件缺失的上下文。
3. 检索个人资料和持久规则，获得与该任务相关的信息或偏好。
4. 查询 iCloud Calendar，检查目标时间是否已有冲突。
5. 若存在缺失信息、歧义或冲突，在对话中向用户追问，而不是自行猜测。
6. 生成“日程预览”和“邮件回复草稿”，将关键字段和实际副作用明确展示给用户。
7. 允许用户分别编辑日程信息和邮件草稿。
8. 用户编辑完成并分别明确确认最终预览内容后，创建 iCloud Calendar 事件并发送 Gmail 回复。
9. 在对话中准确报告执行结果，并将关键来源和执行结果归档到个人资料中。

验收标准：

1. 从手机 Web 端可以完整完成核心场景，不依赖桌面终端或手工修改数据库。
2. 任务不依赖始终开启的桌面对话窗口；用户关闭或刷新页面后，仍可查看和编辑已保存的待确认日程预览及邮件草稿。
3. Agent 能同时调用 Gmail、个人资料和 iCloud Calendar，并在同一任务中共享上下文。
4. 遇到缺失字段、时间冲突或含义不明确时会追问；不会用未经验证的猜测执行写操作。
5. 创建日程和发送邮件前均有清晰预览，并需要独立、明确的用户确认。
6. 重复检查邮箱不会重复处理或发送同一封邮件；重复确认不会重复发送同一项已完成的回复；发送结果不确定时不会直接再次发送。
7. 用户纠正可以持久化，并在新会话中再次影响 Agent 行为。
8. 至少有一个成功流程能够沉淀为可读、可改、可版本管理的 Skill/Workflow。
9. 新邮件同步后，无需用户主动发起请求即可启动 Agent 处理；外部写操作仍须等待明确确认。
10. 执行内容与用户最终确认的内容一致；任务部分成功、部分失败时，在对话中准确说明各项操作的当前情况。
11. 规则和 Skill 的沉淀同时支持模型自主发起与用户明确触发；已生效内容在新会话中继续应用。
12. 自主沉淀 Skill/Workflow 后，在对话中提示用户查看草稿；用户可以审阅、修改触发词、必要参数、执行流程及安全性信息。确认前，草稿在当前会话和新会话中均不得被应用或执行；用户明确确认最终草稿后才投入生产，执行具体外部写操作时仍须单独确认。
